日期：2026-11-14。源音频：上一级目录的《周杰伦 - 晴天.flac》，时长269.747秒。原文件保持不变。

## 先看哪里

1. 双击 `预览.html`，查看15段的图像、时间、实测数值和设计理由；点击“试听该段”可播放本地音频对应范围。
2. `03_LLM输入/song_visual_input.json` 是交给文字LLM的完整结构化输入；`逐段音乐描述.md` 是中文阅读版。
3. `04_视觉方案与提示词/整曲视觉方案.md` 是当前Codex文字LLM根据数据完成的设计输出；每段有独立完整提示词。
4. `05_生成图/S01.png` 至 `S15.png` 是内置imagegen生成的原始概念图；元数据在 `generation_manifest.json`。

## 本轮确实完成的内容

- 完整FLAC的本地读取与SHA256记录；生成未裁剪、未额外响度归一化的22,050 Hz单声道分析副本。
- 全曲RMS、频谱质心、频谱平坦度、频段能量比例、MFCC、色度特征、HPSS成分、起音和节拍计算。
- 约136 BPM节拍估计及68 BPM半速候选；没有人工打拍确认，不宣称拍号或小节第一拍已识别。
- 多尺度结构变化与8/10/12/14/16段时间聚类比较，核对特征图和相似矩阵，形成15个视觉探索用的声学工作段。
- 将音乐证据与视觉解释分开，完成15段文字设计并调用内置imagegen生成各段主图。

## 结果如何理解

15段是v1工作分段，含较细的声学变化。部分边界有多种参数支持，部分仅由局部变化支持；证据在 `02_MIR/segmentation_review.json`。

**没有人工听辨确认的主歌/副歌标签。** 本轮也没有运行预训练乐器、曲风、效价/唤醒、歌词、主旋律或和弦模型，相应输入字段明确为null。不要把声学指标或本轮配色直接当成歌曲情绪的客观结论。

文字模型阶段由当前Codex会话直接读取实测结果并设计，不声称调用了另一个文字API。生图阶段实际使用独立的内置imagegen工具。完整提示词、参考图和原始图片已保存；工具没有提供可记录的模型版本和seed。

全部图片是静态概念图，不是Unity可编辑三维资产，也没有验证连续运动或拍点同步。

- `01_输入`：分析音频、原始参考截图、输入清单。
- `02_MIR`：原始特征、节拍/起音、候选边界、选定分段、相似性检查、图表。
- `03_LLM输入`：测量输入、中文音乐描述、系统提示词、美术约束。
- `04_视觉方案与提示词`：文字设计输出、15份生图提示词和工具请求参数。
- `05_生成图`：15张PNG、来源与哈希清单。
- `scripts`：可复跑的分析、输入整理、设计记录与报告生成脚本。
- `logs`：本轮运行与验证记录。
- `.venv`、`.cache`：此实验的本地依赖与计算缓存。

## 如何重跑

在本目录PowerShell中运行：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\scripts\analyze_music.py
& .\.venv\Scripts\python.exe -X utf8 .\scripts\prepare_llm_input.py
& .\.venv\Scripts\python.exe -X utf8 .\scripts\build_report.py
```

分析脚本会复用 `features_full.npz`；该缓存绑定当前源音频。替换音频时应另建实验版本，或在核对后移走缓存再计算。

`build_visual_plan.py` 保存的是本轮LLM已经完成的设计，不是文字API客户端；换曲或修改分段后，应让文字LLM重新阅读音乐输入并修订设计。

生图调用由Codex内置imagegen执行，不属于上述Python命令。要重新生图，可在Codex里指定某一段的提示词文件和 `imagegen_jobs.json` 中的参考图路径。无需为本轮内置生图填写API密钥。

本地环境依赖版本保存在 `requirements-lock.txt`。图像需要主观审美评审；工作分段需要通过预览页试听进一步确认。
